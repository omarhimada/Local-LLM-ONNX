Below is a practical “recipe” that you can run locally (or integrate into CI) to add a lightweight layer of obfuscation to a self‑contained .NET 10 WPF executable produced with dotnet publish. It uses only open‑source tooling (Mono.Cecil, ILRepacker/ILRepacker) and works against the output that matches your project file:
<!--  net10.0-windows -->
<Configuration>Release</Configuration>
<Platform>AnyCPU</Platform>
<PublishDir>bin\Release\Publish</PublishDir>
<PublishProtocol>FileSystem</PublishProtocol>
<TargetFramework>net10.0-windows</TargetFramework>
<RuntimeIdentifier>win-x64</RuntimeIdentifier>
<SelfContained>true</SelfContained>
<PublishSingleFile>true</PublishSingleFile>
<PublishReadyToRun>true</PublishReadyToRun>
---
1. Build & Publish
cd path/to/your/project
dotnet publish -c Release -r win-x64 /p:PublishSingleFile=true
Afterwards, the output will be located under <project>\bin\Release\net10.0-windows\publish\<app>.exe.
---
2. Install required tools
a) ILRepacker (IL Repacking)
Download the latest release from [GitHub – dotnet ILRepacker](https://github.com/samuelzafrin/IL-Repacker/releases). Unzip it somewhere reachable, e.g.:
C:\tools\ILRepacker\ILRepacker.exe
b) Mono.Cecil (NuGet package)
Add it to a small console helper that we’ll call ObfuscatorHelper.
dotnet new console -n ObfuscatorHelper
cd ObfuscatorHelper
dotnet add package Mono.Cecil --version 6.4.3   // or newer
Replace the auto‑generated Program.cs with the following minimal helper:
using System;
using Mono.Cecil;

class Program
{
    static void Main(string[] args)
    {
        if (args.Length < 1)
        {
            Console.WriteLine("Usage: ObfuscatorHelper <path-to-your-exe>");
            return;
        }

        var asmPath = args[0];
        var assembly = AssemblyDefinition.ReadAssembly(asmPath);

        // Very light weight “obfuscation”:
        // * rename all types/members to random names
        // * remove debug symbols
        // * strip PDBs (they’re separate files anyway)

        foreach (var module in assembly.Modules)
        {
            foreach (var type in module.Types)
            {
                type.Name = $"T{Guid.NewGuid():N}";
                foreach (var method in type.Methods)
                {
                    method.Name = $"M{Guid.NewGuid():N}";
                    method.Body?.SsaVariables.Clear();          // clear SSA vars
                    method.Parameters.Clear();                  // optional stripping
                }
            }
        }

        // Write back
        assembly.Write(assembly.MainModule.ForceFullName + ".renamed.dll");
        Console.WriteLine($"Wrote obfuscated version to {assembly.MainModule.ForceFullName}.renamed.dll");
    }
}
Compile:
dotnet build -c Release
Result: bin\Release\net5.0\ObfuscatorHelper.dll (you can target .NET 8/.NET 10 if desired).
---
3. Apply the helper and repack
$origExe = "bin\Release\net10.0-windows\publish\MyApp.exe"
$helper  = "..\ObfuscatorHelper\bin\Release\net5.0\ObfuscatorHelper.dll"

# 1️⃣ Run the helper → creates MyApp.rateded.dll
&dotnet $helper $origExe

# 2️⃣ Use ILRepacker to combine the result with any dependency DLLs
#     (for a single-file app there are none, but this step ensures
#      the main assembly stays a valid PE.)
$repackedExe = "$($origExe).repacked.exe"
&"C:\tools\ILRepacker\ILRepacker.exe" /out:$repackedExe $origExe*.dll

echo "Final obfuscated single‑file: $repackedExe"
Running the sequence above produces a new executable (*repacks.exe) whose assembly contains mangled identifiers that are harder to read or reverse‑engineer.
Because the binary remains a standard .NET PE, all normal debugging, signing, and packaging features still work.
Feel free to wrap the PowerShell commands in a .ps1 script or a tiny batch file, and call that from your CI pipeline.
---
4. Quick sanity checks
| What you should see | Where to look | |----------------------|--------------| | No obvious strings (like class names) appear in a hex editor | strings <app>.exe or a hex viewer | | App starts normally and displays its UI | Run the resulting <app>.repacks.exe manually | | Signing certificates stay intact (if signed) | signtool verify /pa <app>.repacks.exe |
---
5. Extending the protection
•	Rename resources (images, icons, etc.) with the same helper.
•	Strip the PDB by deleting *.pdb files after publishing.
•	Use a real obfuscator (DotNetGuard, Confiz, SmartAssembly…) if you need control flow flattening, anti‑tamper hooks, etc.
•	Combine with UPX compression (upx --best) if you prefer a smaller footprint.
---
That’s a full, reproducible workflow you can drop into a GitHub Actions job or a local build script. Happy coding—and happy protecting!!
